Dijkstras Sink Tree Algorithm

Dijkstra's algorithm finds the shortest path from a single source vertex to every other vertex in a weighted graph with non-negative edge weights. The sink tree variant flips this perspective: instead of broadcasting shortest paths out from a source, it computes shortest paths into a designated sink — a destination vertex that every other vertex wants to reach. The result is a directed spanning tree rooted at the sink, where every tree edge points toward it and the path from any vertex to the sink along the tree is guaranteed to be the shortest available.

Why flip the direction? In routing and network optimization, you often want to know the cheapest way for many nodes to deliver data to a single collector. Computing one sink tree answers all of those queries simultaneously, in a single pass.

How it works. Run standard Dijkstra on the reverse graph — replace every directed edge $(u \to v, w)$ with $(v \to u, w)$. Then launch Dijkstra from the sink on this reversed graph. The shortest path from the sink to any vertex $v$ in the reversed graph equals the shortest path from $v$ to the sink in the original graph. Collect the parent pointers from Dijkstra's relaxation steps; they form the sink tree.

Worked example. Consider four cities: A, B, C, and D (the sink), with edges A→B (2), A→C (5), B→D (3), C→D (1). Reverse the edges: B→A, C→A, D→B, D→C. Run Dijkstra from D on the reversed graph. D reaches B at cost 3 and C at cost 1; from B, it reaches A at cost 3+2=5; from C, it reaches A at cost 1+5=6. So A's shortest path to D costs 5, through B. The sink tree edges in the original graph are A→B→D and C→D, with A preferring the A→B→D route.

Problem-solving application. Suppose a logistics company has 50 warehouses all shipping to a single distribution hub. Rather than running Dijkstra 50 times (once per warehouse), reverse the road network, run Dijkstra once from the hub, and read off every warehouse's optimal route from the resulting sink tree in $O(1)$ per query. Time complexity remains $O((V + E)\log V)$ using a binary heap — identical to standard Dijkstra, since the reversal is a linear preprocessing step. Whenever a problem involves many-to-one shortest paths, reach for the sink tree before considering repeated single-source runs.
