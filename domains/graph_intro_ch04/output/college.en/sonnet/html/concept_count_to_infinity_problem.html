Count To Infinity Problem

Definition

The count-to-infinity problem is a failure mode in distance-vector routing protocols where a network link goes down and routers — instead of immediately recognizing the failure — slowly increment their route cost toward an agreed-upon "infinity" value through repeated, circular updates. The root cause is that distance-vector protocols share only summarized information (cost to destination), not the full path, so routers cannot detect when their best route loops back through a neighbor that itself depends on them.

Worked Example

Consider three routers in a chain: A — B — C. All run a distance-vector protocol (e.g., RIP, where infinity = 16 hops). Initial state: A reaches C in 2 hops via B; B reaches C in 1 hop directly.

Now the B–C link fails. B immediately sets its cost to C to infinity. Before B can advertise this update, A sends a routine update telling B: "I can reach C in 2 hops." B, which no longer has a direct route, accepts A's advertisement and sets its cost to C at 3 hops (A's 2 + 1 for the hop to A). A then hears from B and updates to 4. B updates to 5. This back-and-forth continues:

| Round | A's cost to C | B's cost to C | |-------|--------------|--------------| | 0 | 2 | ∞ (failed) | | 1 | 2 | 3 | | 2 | 4 | 3 | | 3 | 4 | 5 | | … | … | … | | 8 | 16 | 16 |

Only when both reach 16 does the protocol declare C unreachable — after 8 wasted update rounds and significant convergence delay.

Problem-Solving Application

Three standard mitigations exist, and exam problems often ask you to trace which one would have prevented a given scenario:

  • Split horizon: A refuses to advertise route X back to the neighbor it learned X from. In the example, A would not tell B about C, because A learned that route through B.
  • Poison reverse: A actively advertises cost ∞ to B for any route learned through B, speeding up failure detection.
  • Hold-down timers: After hearing a route fail, a router ignores cheaper-looking updates for a fixed period, preventing premature re-adoption of a stale path.

    • When diagnosing a slow-convergence scenario on a routing exam, check whether any of these safeguards is missing or misconfigured — that gap is almost always the proximate cause.
