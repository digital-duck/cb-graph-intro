Minimum Spanning Tree

A spanning tree of a connected, undirected graph is a subgraph that includes every vertex and is a tree — meaning it is connected and contains no cycles. If each edge carries a weight (distance, cost, latency), the minimum spanning tree (MST) is the spanning tree whose total edge weight is as small as possible. For a graph with $n$ vertices, any spanning tree has exactly $n - 1$ edges.

MSTs appear wherever you need to connect things cheaply: laying fiber-optic cable between cities, designing circuit boards, clustering data points, or building road networks. The goal is always the same — full connectivity at minimum total cost.

Kruskal's algorithm builds an MST greedily by edge weight:

  • Sort all edges by weight, ascending.
  • Initialize each vertex as its own component (a union-find structure tracks this).
  • Iterate through the sorted edges. For each edge $(u, v, w)$: if $u$ and $v$ are in different components, add the edge to the MST and merge their components. Otherwise, skip it (adding it would create a cycle).
  • Stop when $n - 1$ edges have been added.

    • Worked example. Consider five cities connected by roads with the following edges and distances (km):

    | Edge | Weight | |------|--------| | A–B | 4 | | A–C | 2 | | B–C | 5 | | B–D | 10 | | C–D | 3 | | D–E | 7 |

    Sorted: A–C (2), C–D (3), A–B (4), B–C (5), D–E (7), B–D (10).

  • Add A–C (2): merges {A} and {C}.
  • Add C–D (3): merges {A,C} and {D}.
  • Add A–B (4): merges {A,C,D} and {B}.
  • Skip B–C (5): B and C already connected.
  • Add D–E (7): merges {A,B,C,D} and {E}.

    • MST edges: {A–C, C–D, A–B, D–E}, total cost = $2 + 3 + 4 + 7 = 16$ km.

    Applying this. Suppose you are given a network of $n$ servers and must add the minimum total cable length to make them all reachable from each other. Model servers as vertices and possible cable runs as weighted edges. Run Kruskal's (or Prim's algorithm, which grows the MST outward from a starting vertex). The key insight is that the greedy choice — always taking the cheapest safe edge — is globally optimal here, because any cycle-free edge that connects two previously disconnected components can only help. The correctness of this greedy strategy is guaranteed by a cut property: for any partition of vertices into two sets, the minimum-weight edge crossing the cut belongs to some MST.
