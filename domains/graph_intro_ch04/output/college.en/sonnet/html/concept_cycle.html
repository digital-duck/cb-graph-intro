Cycle

A cycle in a graph is a closed path — a sequence of distinct vertices $v_1, v_2, \ldots, v_k, v_1$ where each consecutive pair shares an edge, and the path returns to its starting vertex without repeating any node. The length of a cycle is the number of edges it contains. A cycle of length 3 is a triangle; a cycle of length $n$ visiting every vertex exactly once is a Hamiltonian cycle.

Cycles matter in practice because they represent circular dependencies, feedback loops, and redundant connections — structures that can either be desirable (fault-tolerant networks) or problematic (deadlocks in scheduling, infinite recursion in logic).

Worked example. Consider a directed graph representing task dependencies:

A → B → C → A      (tasks A, B, C form a cycle)
D → E              (D and E do not)

To detect whether a cycle exists, run a depth-first search (DFS) and track two sets: visited (nodes seen at all) and in-stack (nodes on the current DFS path). If you reach a node already in the current stack, you have found a back edge — and therefore a cycle.

def has_cycle(graph):
    visited, in_stack = set(), set()

    def dfs(node):
        visited.add(node)
        in_stack.add(node)
        for neighbor in graph.get(node, []):
            if neighbor not in visited:
                if dfs(neighbor):
                    return True
            elif neighbor in in_stack:
                return True
        in_stack.remove(node)
        return False

    return any(dfs(n) for n in graph if n not in visited)

graph = {"A": ["B"], "B": ["C"], "C": ["A"], "D": ["E"], "E": []}
print(has_cycle(graph))   # True

Problem-solving application. Cycle detection is central to topological sorting: a directed acyclic graph (DAG) can be sorted so every edge points forward in the ordering, but if any cycle exists, no valid topological order is possible. Build systems (Make, Bazel) and package managers use exactly this check — if package X depends on Y and Y depends on X, the installer reports a circular dependency error rather than looping forever. To resolve such a cycle, you either break the dependency (refactor the packages) or introduce a versioned snapshot that severs the loop. Recognizing where cycles appear — and whether to preserve or eliminate them — is one of the most transferable skills in applied graph reasoning.
