覆盖网络

定义。 覆盖网络(overlay network)是建立在已有底层网络之上的一层虚拟网络。覆盖网络中的节点通过"逻辑链路"相连,每条逻辑链路在底层网络中可能对应一条跨越多个路由器的真实路径。覆盖网络不改变底层的物理线路,只是在其上重新定义"谁与谁直接相邻"以及"消息如何转发"。常见例子有:BitTorrent 与 IPFS 等点对点网络、VPN、内容分发网络(CDN),以及本项目中把多台机器组织成分布式推理集群的 Momagrid。

核心思想。 底层网络(如互联网)只负责把数据包送到某个 IP 地址;覆盖网络则在应用层增加自己的寻址与路由规则,例如"按内容查找"、"选延迟最低的邻居"或"加密隧道"。代价是额外的封装开销和延迟,收益是灵活性:无需修改底层设施,就能部署新的拓扑与服务。

例题。 设底层网络中 A、B、C 三台主机,实际路径为 A–R1–B 与 A–R2–R3–C,其中每个路由器跳数记为 1。在覆盖网络中,我们让 A 的邻居为 B 和 C,B 与 C 不直接相连。

  • 逻辑链路 $A\to B$ 对应底层 2 跳;
  • 逻辑链路 $A\to C$ 对应底层 3 跳;
  • 消息从 B 发往 C,必须经过 A 中转,逻辑路径为 $B\to A\to C$,底层总跳数为 $2+3=5$。

    • 假设 B 与 C 之间的底层直连路径仅需 3 跳,则覆盖路径的"拉伸系数"(stretch)为

    $$ \text{stretch}=\frac{\text{覆盖路径的底层跳数}}{\text{最短底层路径跳数}}=\frac{5}{3}\approx 1.67 . $$

    这说明覆盖网络的拓扑选择会带来性能损失。

    问题求解应用。 假设你要为 8 台机器的推理集群设计覆盖拓扑,希望任意两节点间逻辑跳数尽量少,同时每个节点的连接数不超过 3。

  • 方案一:环形。 每个节点只连两个邻居,最坏逻辑跳数为 $\lfloor 8/2\rfloor=4$,连接少、维护简单,但延迟高。
  • 方案二:超立方体。 将节点编号为 3 位二进制数,与仅有一位不同的节点相连,每个节点恰好 3 条连接,最坏跳数为 3。
  • 方案三:星形(中心调度器)。 最坏跳数为 2,但中心节点需承担 7 条连接,一旦失效整个网络瘫痪。

    • 在连接数受限的条件下,方案二在跳数与可靠性之间取得了较好折中。这体现了覆盖网络设计的通用思路:先明确约束(连接数、容错、延迟),再比较不同拓扑的跳数与拉伸,而不是只追求某一项指标。

    小结。 覆盖网络用软件定义的逻辑拓扑换取部署灵活性;评估其优劣时,应同时考察跳数、拉伸系数和单点故障风险。
