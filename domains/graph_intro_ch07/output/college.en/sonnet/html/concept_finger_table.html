Finger Table

In a distributed hash table (DHT) built on the Chord protocol, every participating node is responsible for storing certain keys. The naive approach — each node knowing only its immediate neighbor — forces a lookup to hop through every node in the ring, which scales terribly as the network grows. A finger table solves this by giving each node a compact set of "shortcuts" that allow any key to be located in $O(\log N)$ hops, where $N$ is the number of nodes.

Each node in Chord occupies a position on an identifier ring of size $2^m$ (typically $m = 160$, using SHA-1 hashes). Node $n$'s finger table has $m$ entries. The $i$-th entry stores the identity of the first node that is at least as far along the ring as position

$$n + 2^{i-1} \pmod{2^m}, \quad i = 1, 2, \ldots, m.$$

The first entry is simply the immediate successor. Each subsequent entry jumps roughly twice as far around the ring, so the table covers the entire identifier space with exponentially increasing strides.

Worked example. Suppose $m = 4$, giving a ring of size $2^4 = 16$. Node $6$'s finger table entries point to the first live node at or after positions $7, 8, 10,$ and $14$. If the ring currently has nodes at $\{1, 3, 6, 10, 13\}$, then node $6$'s table is:

| $i$ | Start position | Successor stored | |-----|---------------|-----------------| | 1 | 7 | 10 | | 2 | 8 | 10 | | 3 | 10 | 10 | | 4 | 14 | 1 |

Problem-solving application. Say node $6$ must locate the key hashed to position $12$. It checks its finger table for the largest entry whose start position does not exceed $12$ — that is entry 3, pointing to node $10$. It forwards the request to node $10$, which now checks its finger table. Node $10$'s table has an entry pointing to node $13$, which owns position $12$. The lookup reaches the correct node in two hops instead of potentially traversing all five nodes sequentially.

When a new node joins or an existing node leaves, only $O(\log N)$ finger table entries across the network require updating — preserving the protocol's efficiency without a global rebuild. This makes finger tables a foundational example of how a small, carefully structured local index can yield globally efficient behavior in a decentralized system.
