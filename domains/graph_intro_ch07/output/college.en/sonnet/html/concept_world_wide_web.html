World Wide Web

The World Wide Web (WWW) is a system of interlinked hypertext documents and resources accessed via the Internet. It is not the Internet itself — the Internet is the underlying network of connected computers — but rather an application layer built on top of it. The Web operates through three core technologies: URLs (Uniform Resource Locators) that identify resources, HTTP/HTTPS (HyperText Transfer Protocol) that governs how clients and servers communicate, and HTML (HyperText Markup Language) that structures the content delivered to browsers.

When you type a URL into a browser, a precise sequence unfolds. The browser performs a DNS lookup to translate the human-readable domain name (e.g., example.com) into an IP address. It then opens a TCP connection to the server at that address and sends an HTTP request. The server responds with a status code and, if successful (200 OK), the requested resource — typically an HTML file. The browser parses the HTML, discovers additional resources (images, stylesheets, scripts), fetches those, and renders the complete page.

Worked example. Consider a student visiting https://en.wikipedia.org/wiki/Python. The browser contacts a DNS resolver and learns the server's IP. Because the URL uses HTTPS, it also performs a TLS handshake to establish an encrypted connection before any data is exchanged. It then sends:

GET /wiki/Python HTTP/1.1
Host: en.wikipedia.org

The server returns a 200 response whose body is the HTML for that page. Embedded <img> and <link> tags trigger additional GET requests for images and CSS. The browser assembles all pieces into the rendered page the student sees.

Problem-solving application. Suppose a developer's webpage loads slowly. Diagnosing it requires understanding the Web's layered model. Using browser developer tools (Network tab), they can inspect each HTTP request: which resources are largest, which take longest, and whether any return error codes (404 Not Found, 503 Service Unavailable). Fixes might include compressing images or serving assets from a CDN located geographically closer to users. Each intervention maps directly to a bottleneck in the request-response cycle — no fix is meaningful without understanding the underlying flow.
