Autonomous System

The internet is not a single network run by one organization — it is a patchwork of tens of thousands of independently managed networks that agree to exchange traffic with each other. Each of those independently managed networks is called an autonomous system (AS). Formally, an autonomous system is a collection of IP address prefixes under the control of a single administrative entity (a university, a corporation, an internet service provider) that presents a unified routing policy to the rest of the internet. Every AS is assigned a globally unique Autonomous System Number (ASN) by a regional internet registry — for example, Cloudflare operates AS13335 and Google operates AS15169.

Inside an AS, routers can use whatever internal routing protocol the operator chooses (OSPF, IS-IS, EIGRP). What makes the AS boundary meaningful is what happens at the edge: neighboring ASes exchange reachability information using the Border Gateway Protocol (BGP), the protocol that stitches all autonomous systems into the global internet.

Worked example. Suppose you are on a university campus (AS 11111) and you request a webpage hosted at a company's data center (AS 22222), with a regional ISP (AS 33333) sitting between them. Your university's border router speaks BGP with the ISP's router. The ISP's router speaks BGP with the company's router. Each AS advertises the IP prefixes it owns: the company says "I own 203.0.113.0/24." The ISP relays that advertisement to your university. When your packet leaves campus, your border router knows to forward it toward AS 33333, which forwards it toward AS 22222 — all because of AS-level routing agreements, not because any single router knows the full path end-to-end.

Problem-solving application. Diagnosing cross-network failures requires thinking in AS terms. If traceroute shows your packets reaching AS 33333 but never arriving at AS 22222, the problem is almost certainly a BGP peering failure or a missing route advertisement between those two ASes — not a misconfiguration inside your own campus. Tools like whois -h whois.radb.net AS22222 or looking up an ASN on a public BGP looking-glass let you check what prefixes an AS is currently advertising, which narrows the fault to the right administrative boundary. This ability to isolate faults by AS is why the concept exists: it maps technical routing domains onto the organizational boundaries where human operators actually have authority to fix things.
