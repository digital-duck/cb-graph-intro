Triple

A triple is an ordered, fixed-length sequence of exactly three values. In Python, a triple is simply a tuple with three elements: (a, b, c). Because tuples are immutable, a triple is a natural choice when three related values belong together and should not be altered — a 3-D coordinate, an RGB color, or a database record key. The three positions carry meaning by convention: swapping them produces a different object even if the values are identical.

Formally, a triple belongs to the Cartesian product $A \times B \times C$, meaning the first element comes from set $A$, the second from $B$, and the third from $C$. When all three sets are the same (say, real numbers), you write $\mathbb{R}^3$.

Worked example. Suppose you are building a knowledge graph where every fact is stored as a (subject, predicate, object) triple:

facts = [
    ("Alice", "knows", "Bob"),
    ("Bob",   "works_at", "CERN"),
    ("Alice", "works_at", "MIT"),
]

def query(facts, predicate):
    return [(s, o) for s, p, o in facts if p == predicate]

print(query(facts, "works_at"))
# [('Bob', 'CERN'), ('Alice', 'MIT')]

Unpacking s, p, o in the loop is idiomatic Python: it names each position without an index, making the intent self-documenting.

Problem-solving application. Many geometric algorithms pass points as triples. Consider computing the centroid of a triangle given its three vertices:

def centroid(v1, v2, v3):
    x = (v1[0] + v2[0] + v3[0]) / 3
    y = (v1[1] + v2[1] + v3[1]) / 3
    z = (v1[2] + v2[2] + v3[2]) / 3
    return (x, y, z)

A = (0.0, 0.0, 0.0)
B = (3.0, 0.0, 0.0)
C = (0.0, 4.0, 0.0)
print(centroid(A, B, C))   # (1.0, 1.333..., 0.0)

The centroid formula is $G = \left(\frac{x_1+x_2+x_3}{3},\; \frac{y_1+y_2+y_3}{3},\; \frac{z_1+z_2+z_3}{3}\right)$, and returning it as a triple keeps the result in the same shape as the inputs — a design discipline that makes function composition easier.

When choosing between a triple and a small class, prefer a triple for read-only, positional data (coordinates, colors, graph edges); prefer a class when the data needs methods or when positional semantics would confuse future readers.
