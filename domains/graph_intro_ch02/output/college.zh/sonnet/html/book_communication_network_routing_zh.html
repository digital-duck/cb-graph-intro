通信网络路由:殊途同归的终点

本书一路走来,从图的表示、最短路径,到流量与容量,再到分布式协议。通信网络路由(communication network routing)把这些内容汇合到一个问题上:在一个由节点和链路构成的网络中,如何为每一份数据选择一条从源到目的地的路径,使整体代价最小、同时满足容量与可靠性约束?

它是自然的终点,原因有三:

  • 综合性:它同时用到图的建模、最短路径算法、容量约束和分布式决策。
  • 可检验性:路由的好坏可以直接测量,包括延迟、吞吐量和丢包率。
  • 规模性:真实网络有成千上万个节点,没有任何节点掌握全局信息,所以算法必须能够分布式运行。

    • 工作示例:用最短路径选路

    把网络看作加权图 $G=(V,E)$,每条链路 $(u,v)$ 有代价 $w(u,v)$(例如延迟,单位为毫秒)。从源 $s$ 到目的地 $t$ 的最优路径满足:

    $$ d(t)=\min_{P:\,s\to t}\ \sum_{(u,v)\in P} w(u,v). $$

    下面用 Dijkstra 算法实现,并输出路径:

    import heapq

def route(graph, s, t):
    dist = {s: 0}
    prev = {}
    pq = [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if u == t:
            break
        if d > dist.get(u, float("inf")):
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                prev[v] = u
                heapq.heappush(pq, (nd, v))
    path, node = [], t
    while node != s:
        path.append(node)
        node = prev[node]
    return [s] + path[::-1], dist[t]

g = {"A": [("B", 2), ("C", 5)], "B": [("C", 1), ("D", 4)],
     "C": [("D", 1)], "D": []}
print(route(g, "A", "D"))   # (['A','B','C','D'], 4)

    直接走 A→C→D 的代价是 6,而 A→B→C→D 的代价是 4。局部上看起来更短的"直连"并不是全局最优。

    问题求解:链路故障与负载均衡

    如果链路 $(B,C)$ 失效,把它从图中删除后重新运行算法,新路径为 A→C→D,代价为 6。这正是 OSPF 等链路状态协议的基本思路:检测到变化,广播,重算。

    如果许多流量都选择同一条最短路径,这条链路就会拥塞。这时可以把代价改为随负载增长的函数,例如 $w_e(x)=w_e^0\,(1+x/c_e)$,其中 $x$ 为当前流量,$c_e$ 为容量,使流量自动分散到多条路径上。

    与各应用领域的联系

    由于本节未列出具体的应用领域,下面按路由思想最常见的几类场景说明它的延伸:

  • 互联网骨干与数据中心:BGP、OSPF 与 ECMP 都是上述模型的工程化版本。
  • 分布式计算与推理网格:把任务调度到不同节点,本质上是在"计算—通信"代价图上选路。
  • 交通与物流:道路网络的导航和配送优化使用同样的最短路径与拥塞模型。
  • 无线与物联网:能耗和链路质量取代延迟成为代价,需要在动态拓扑上重新选路。
