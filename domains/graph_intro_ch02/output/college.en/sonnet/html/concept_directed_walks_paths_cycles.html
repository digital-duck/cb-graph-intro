Directed Walks, Paths, and Cycles

A directed graph (digraph) assigns a direction to every edge: an edge from vertex $u$ to vertex $v$ is written $(u, v)$ and can only be traversed in that order. Once you add direction, the way you move through the graph becomes more structured — and three terms describe the kinds of movement precisely.

A directed walk is any sequence of vertices $v_0, v_1, v_2, \ldots, v_k$ such that $(v_i, v_{i+1})$ is a directed edge for each consecutive pair. Vertices and edges may repeat freely. A directed path tightens this: no vertex may appear more than once. A directed cycle is a closed walk — it starts and ends at the same vertex — in which no intermediate vertex repeats.

These distinctions matter because they correspond to qualitatively different situations in real systems. A walk models any sequence of hops (a packet bouncing through routers, possibly revisiting nodes). A path models a route with no backtracking (a courier's delivery sequence). A cycle signals the possibility of looping behavior (a dependency loop in a build system, a feedback loop in a state machine).

Worked example. Consider the digraph with edges $(A,B)$, $(B,C)$, $(C,A)$, $(B,D)$, and $(D,C)$. Is the sequence $A \to B \to D \to C \to A$ a walk, a path, or a cycle?

  • Every consecutive pair is a directed edge. ✓ It is a walk.
  • No vertex repeats until the final return to $A$. ✓ It is a cycle.

    • Now consider $A \to B \to C \to A \to B$. This is a walk (edges exist at each step), but not a path (vertex $A$ and $B$ both repeat) and not a simple cycle (it doesn't return cleanly to the start without repeating).

    Problem-solving application. Detecting cycles in a digraph is a core task in software dependency resolution. If package $X$ depends on $Y$, and $Y$ depends on $X$, the dependency graph contains a directed cycle — and no installation order can satisfy both requirements. A standard solution is depth-first search with coloring: mark each vertex white (unvisited), gray (in progress), or black (done). If DFS ever reaches a gray vertex, a back edge exists, confirming a cycle. The algorithm runs in $O(V + E)$ time, making it practical even for graphs with thousands of packages.

    The key habit: always ask whether your problem needs a walk (repetition allowed), a path (no revisits), or a cycle (closed loop) — the right structure determines which algorithm to reach for.
