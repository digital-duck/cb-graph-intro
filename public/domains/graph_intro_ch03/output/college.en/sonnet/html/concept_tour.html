Tour

A tour in graph theory is a walk through a graph that returns to its starting vertex. More precisely, a tour visits edges (or vertices) according to some rule and closes back on itself, forming a cycle. Two classic variants drive most practical applications: an Eulerian tour crosses every edge exactly once, while a Hamiltonian tour visits every vertex exactly once. Knowing which kind of tour exists — and how to find it — determines whether a routing problem is easily solvable or computationally hard.

Eulerian tour. Euler's 1736 result on the Königsberg bridge problem gives the definitive condition: a connected undirected graph has an Eulerian tour if and only if every vertex has even degree. This is one of the cases where a formal theorem genuinely matters, because it converts an infinite search into a single degree-parity check.

Worked example. Consider a small delivery network modeled as a graph:

import networkx as nx

G = nx.MultiGraph()
edges = [(0,1),(0,1),(1,2),(2,3),(3,0),(1,3)]
G.add_edges_from(edges)

# Check Eulerian tour existence
degrees = dict(G.degree())
print("Degrees:", degrees)
print("Eulerian tour exists:", all(d % 2 == 0 for d in degrees.values()))

# Find the tour
if nx.is_eulerian(G):
    tour = list(nx.eulerian_circuit(G))
    print("Tour:", tour)

Every vertex has even degree here, so the graph is Eulerian and the circuit is found in $O(|E|)$ time using Hierholzer's algorithm.

Problem-solving application. Route-optimization problems frequently reduce to tour existence checks. A snowplow must traverse every street (edge) and return to the depot — that's an Eulerian tour problem. If some vertices have odd degree, you add the minimum number of duplicate edges to make all degrees even (the Chinese Postman strategy), then find the Eulerian circuit on the augmented graph.

Hamiltonian tours — visiting every city exactly once in a sales route — look superficially similar but belong to a different complexity class (NP-hard in general). The practical lesson: always identify which tour type your problem requires before choosing an algorithm. Confusing the two leads to either an exponential algorithm where a linear one suffices, or an incorrect model that misses repeated edges entirely.
