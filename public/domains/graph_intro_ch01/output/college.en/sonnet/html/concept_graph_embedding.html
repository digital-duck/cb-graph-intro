Graph Embedding

A graph embedding maps the nodes (and sometimes edges) of a graph into a continuous vector space — typically $\mathbb{R}^d$ for some small dimension $d$ — so that nodes that are structurally similar or closely connected end up near each other geometrically. The idea is to translate the discrete, relational structure of a graph into numbers that standard machine-learning algorithms can consume: you cannot feed a social network directly into a neural network, but you can feed a list of 128-dimensional vectors.

The guiding principle is proximity preservation: if nodes $u$ and $v$ share an edge or frequently appear in the same neighborhood, their embedding vectors $\mathbf{z}_u$ and $\mathbf{z}_v$ should have high cosine similarity or small Euclidean distance. Formally, an embedding function $f: V \to \mathbb{R}^d$ is trained so that

$$\text{similarity}(\mathbf{z}_u, \mathbf{z}_v) \approx \text{graph\_proximity}(u, v).$$

What "graph proximity" means varies by method. Node2Vec defines it through random walks: it samples many short walks starting from each node, then treats each walk like a sentence and each node like a word, feeding the sequences into a Word2Vec-style skip-gram model. The result is that nodes visited together in walks get pulled toward each other in embedding space.

Worked example. Consider a citation network where each node is a paper and each edge means "paper A cites paper B." Running Node2Vec produces a 64-dimensional vector for every paper. After embedding, you can cluster papers with k-means to discover research communities, or train a logistic regression to predict whether two papers belong to the same field — using only the dot product of their embedding vectors as a feature.

Problem-solving application. Suppose you need to recommend new connections in a professional network. Raw adjacency data is too sparse and high-dimensional for direct comparison. Instead: (1) embed all nodes into $\mathbb{R}^{128}$ using Node2Vec; (2) for a target user $u$, retrieve the top-$k$ nodes by cosine similarity to $\mathbf{z}_u$ that are not yet connected to $u$; (3) rank those candidates and surface them as recommendations. This pipeline runs efficiently even on graphs with millions of nodes because similarity search in $\mathbb{R}^{128}$ is far cheaper than graph traversal over the full adjacency structure. Embeddings also generalize: the same vectors can power link prediction, anomaly detection, and node classification without rerunning expensive graph algorithms for each task.
