Graph

A graph is a mathematical structure used to model relationships between objects. It consists of a set of vertices (also called nodes) and a set of edges that connect pairs of vertices. Formally, a graph $G = (V, E)$ where $V$ is the vertex set and $E \subseteq V \times V$ is the edge set. Edges can be undirected (a two-way connection, like a road between two cities) or directed (a one-way connection, like a hyperlink from one webpage to another). A graph can also carry weights on its edges — numerical values representing cost, distance, or capacity.

Graphs are the natural language for problems involving networks: social connections, routing, scheduling, and dependency resolution all reduce to graph problems.

Worked example. Consider a small network of five cities connected by roads:

import networkx as nx

G = nx.Graph()
G.add_edges_from([
    ("A", "B", {"weight": 4}),
    ("A", "C", {"weight": 2}),
    ("B", "D", {"weight": 5}),
    ("C", "D", {"weight": 1}),
    ("D", "E", {"weight": 3}),
])

Here $|V| = 5$ and $|E| = 5$. The degree of a vertex is the number of edges incident to it; vertex D has degree 3 because it connects to B, C, and E. The path A → C → D has total weight $2 + 1 = 3$, which is shorter than A → B → D at weight $4 + 5 = 9$.

Problem-solving application. Graphs become powerful when you apply traversal and search algorithms to extract information. Suppose you want the shortest path from A to E in the weighted graph above. Dijkstra's algorithm explores vertices in order of cumulative distance and guarantees the optimal path:

path = nx.dijkstra_path(G, "A", "E", weight="weight")
cost = nx.dijkstra_path_length(G, "A", "E", weight="weight")
print(path, cost)   # ['A', 'C', 'D', 'E']  6

The algorithm finds A → C → D → E with total weight 6, beating every alternative. This same pattern — model relationships as a graph, then query with a standard algorithm — solves problems ranging from GPS routing to compiler dependency checks to recommendation engines. Recognizing that a problem has graph structure is often the key insight; once you see it, a well-tested algorithm almost always exists.
