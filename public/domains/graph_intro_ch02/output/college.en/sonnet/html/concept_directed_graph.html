Directed Graph

A directed graph (or digraph) is a set of nodes connected by edges that each carry a direction — an arrow pointing from one node to another. Formally, a directed graph $G = (V, E)$ consists of a vertex set $V$ and an edge set $E \subseteq V \times V$, where each edge $(u, v)$ is an ordered pair meaning "there is a connection from $u$ to $v$." The reverse edge $(v, u)$ is a separate, independent relationship that may or may not exist.

This directional asymmetry makes directed graphs the natural model for any system where relationships are one-way or carry a specific flow: web pages linking to other pages, dependencies between software packages, prerequisites in a course catalog, or money moving between bank accounts.

Worked Example. Consider four courses: Math 101, CS 101, CS 201, and CS 301, where a student must complete certain courses before enrolling in others.

Math 101 → CS 201
CS 101   → CS 201
CS 201   → CS 301

This is a directed graph with $V = \{\text{Math 101, CS 101, CS 201, CS 301}\}$ and three directed edges. Notice that CS 101 and Math 101 both point into CS 201, but CS 201 does not point back — there is no circular dependency. A path from CS 101 to CS 301 exists: CS 101 → CS 201 → CS 301. No path exists from CS 301 back to CS 101, which correctly reflects that completing an advanced course doesn't retroactively satisfy a prerequisite.

Problem-Solving Application. A common task on directed graphs is detecting a cycle — a path that starts and ends at the same node. Cycles matter because they signal a contradiction: if package A depends on B and B depends on A, neither can be installed first. The standard algorithm is depth-first search (DFS) with a "currently visiting" flag. As DFS explores each node, it marks it in progress; if it ever encounters an in-progress node again, a cycle exists. This runs in $O(|V| + |E|)$ time.

When working with directed graphs, always ask two diagnostic questions: Which direction does each edge flow? and Are there cycles? Direction determines reachability; cycles determine whether a valid ordering (called a topological sort) is even possible. Both questions drive most real-world graph algorithms, from build systems to recommendation engines.
